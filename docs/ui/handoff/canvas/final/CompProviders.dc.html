PartRule
Header (§11M 1.10)Stats sit under the title and facts, in one wrapping HeaderStatGroup, for every provider (Session.dc.html redrawn). Order: ProviderMark → title + subtitle → SessionFacts → stats.
Facts without bodiesCodex facts are what metadata gives: cwd, approval, sandbox, origin. Shell and timezone are only in the prompt’s environment block (content), so they appear only when bodies are recorded. Absent facts are left out, no placeholder.
Word: PromptsOne word across providers: Prompts. On Codex the tab hint says Codex calls a prompt a turn.
Tab labels & TabHintUnchanged from §11L.7.
Request filtersToggleChip (§11G.B2), as on Session.dc.html: pressed = ink fill + ✓, unpressed muted; square swatches. ALL is pressed by default. Chips only for channels with a count above 0.
Request rowsCanonical RequestRow columns and headings for every provider (Time, #, Kind, Meth, Path · detail, Status, Dur, Up, Down; person scope swaps # for Session). Only Detail’s text follows §11L.6. Since # already holds the prompt, Detail starts at step <n>. Codex WebSocket turns read WS in Method.
Long turnCanonical PromptRow columns; the step count goes in the steps column (203). The StepStrip, StepRun and paging rules from §11L.7 hold.
No recorded bodies (§11M 3.1)The default for customer installs. A row shows only what metadata gives: kind, tool counts, tokens, timing, stop reason. Dropped, with nothing in their place: commands, exit codes and failures, patch targets and line counts, text excerpts, prompt text. Prompt text becomes its length (412 chars), as Claude Code’s prompt rows already do. Step kind and tool counts are metadata, so exec ×2 and apply_patch ×1 stay; a text-only step reads text. A tool-call model row is therefore identical with and without bodies; only text rows and step details change.
Runs without bodiesA run is still consecutive command-only steps (kind is metadata). It keeps step count, tool counts, span and tokens, plus whatever the agent’s own analytics carry. Claude Code: its analytics report each Bash command’s program (bash_argv0) and exit code in any mode, so its runs show programs (npm ×14, rg ×5) and failures (exit ≠ 0 ×6, --danger) with or without bodies. Full commands still need bodies. Codex: its analytics report no commands, so without bodies a Codex run has tool counts only and no failing variant.
