# Harness parity: coding agents

What each coding harness gives us, how it maps onto AIntercept's common schema, and
where AIntercept stands. Keep this current: when a capture shows a new field or a
harness ships a feature, update its cell; when AIntercept starts or finishes support,
update the last two columns. Browsers (ChatGPT web, claude.ai) get their own table
when that work starts.

The architecture it tracks: the proxy captures raw traffic unchanged; one rollup per
harness turns it into the common shaped tables (person, device, session, prompt,
model call, tool call, event, coverage, limits, capabilities), each row tagged with
its provider and product plus an `ext` bag for what only that harness has; the API
and UI read the common shape.

**Cells.** What the harness sends and where it comes from. `—`: the harness doesn't send it.

**Mapping.**
- **common:** one generic source serves every harness.
- **mapped:** the same concept, each harness its own source (its rollup's job).
- **bespoke:** one harness only (lives in `ext`, shown in a provider-specific place).

**AIntercept.**
- **shown:** in the UI.
- **served:** the API serves it; the UI doesn't show it yet.
- **extracted:** in the shaped data, not yet in the UI.
- **captured:** in raw capture only.
- **missing:** not captured, or captured but unparsed.

Evidence: Claude Code from the capture since 2026-11-02. Codex CLI 0.164 (TUI 0.167) from runs
through the proxy on 2026-11-02 and 2026-11-08: 2,387 requests, 29 threads, 184 model
turns. The runs covered exec, TUI, resume, fork, review, subagents, MCP, web search,
images, interrupts and a second model. Last reviewed 2026-11-08.

## Identity

| Concept | Claude Code | Codex | Mapping | AIntercept (Claude Code / Codex) |
|---|---|---|---|---|
| Person (account) | `account_uuid` (analytics, OAuth) | `chatgpt-account-id` header, `account_uuid` | mapped | shown / served (linked by email) |
| Name, email | `/api/oauth/profile`, `/api/claude_cli/bootstrap` responses | JWT claims on every call (email, name, plan, user id) | mapped | shown / served (accounts table) |
| Org / workspace | `organization_uuid`, `x-organization-uuid` | the ChatGPT account id is the workspace | mapped | shown / captured |
| Plan, limits | `utilization7d`, overage (rate-limit headers) | `x-codex-plan-type`, 5 h and weekly windows (used %, reset), credits | mapped | shown / served (`agentLimits`) |
| Device | `device_id` + env (platform, arch, terminal, shell) | `installation_id` + user-agent OS/arch | mapped | shown / extracted |
| Client version | user-agent `claude-cli/…` | user-agent + `originator`: `codex_exec` (non-interactive), `codex-tui` (interactive), `codex_cli_rs`, `codex-mcp-client`; OS, arch, terminal in the user-agent | common | shown / served (`client`, `clientVersion`) |

| Presence (focus, sleep) | analytics | — | bespoke (Claude Code) | shown / — |
| Recaps | analytics | — | bespoke (Claude Code) | shown / — |
| Experiments, flags | GrowthBook / Statsig | `x-codex-beta-features` (a list) | bespoke | shown / captured |
